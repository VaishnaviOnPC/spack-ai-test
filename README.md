# Spack AI-Test: Generative-AI Assisted Testing of Complex Packages

`spack-ai-test` is an advanced Spack extension that leverages Large Language Models (LLMs) to perform risk-guided configuration fuzzing. By navigating Spack's exponentially large configuration space (versions, variants, dependencies, and compilers), it autonomously discovers undeclared toolchain incompatibilities and dependency regressions that traditional combinatorial testing and CI pipelines miss.

Built on a self-adaptive **MAPE-K (Monitor, Analyze, Plan, Execute, Knowledge)** architecture, the framework learns from its own historical tests and actively mines external signals to intelligently target the most vulnerable regions of a package's configuration space.

## Features

- **Multi-Source RAG Context**: Augments LLM prompts with:
  - **Live Version Gap Analysis**: Queries the Spack registry for unchecked major version boundaries.
  - **Global Pattern Mining**: Identifies historical features that systematically cause cluster-wide concretization or build failures.
  - **GitHub Signal Integration**: Scrapes a package's GitHub repository for active issue/PR ratios and recent bug reports (e.g., segfaults, build errors).
- **Static Pre-Validation**: Prevents LLM hallucinations (invalid versions, non-existent variants) from wasting concretizer time or polluting the Knowledge Base (KB).
- **Failure Classification**: Analyzes build logs to separate true package defects from transient environment or exogenous dependency failures.
- **Automated Defect Localization (Bisection)**: Automatically triggers upon deterministic build/test failures. Uses a two-phase search (exponential galloping followed by binary search) to pinpoint the exact package version that introduced a regression in $\mathcal{O}(\log d)$ time.
- **Offline & CI Workflows**: Split execution modes (`--plan-only` and `--execute-queued`) allow LLM generation on login nodes and offline concretization/testing on compute nodes.

## Installation

Clone the repository into your Spack extensions directory:

```bash
git clone https://github.com/VaishnaviOnPC/spack-ai-test /path/to/spack-ai-test
```

Register it in your Spack configuration (`~/.spack/config.yaml`):

```yaml
config:
  extensions:
  - /path/to/spack-ai-test
```

Verify the installation:
```bash
spack ai-test --help
```

## Usage and Flags

### Basic Inspection
```bash
# Print package structural risk info to the terminal
spack ai-test zlib

# Dump raw JSON schema extraction
spack ai-test zlib --json
```

### LLM Spec Generation
```bash
# Use an LLM to generate test scenarios for a package (dry-run, no execution)
spack ai-test openmpi --generate

# Generate and queue specs in the KB without executing them (Login Node Mode)
spack ai-test openmpi --plan-only
```

### Full MAPE-K Execution
```bash
# Run the full loop: generate specs, concretize them, and save to KB
spack ai-test openmpi --mape

# Also attempt to build the concretized specs
spack ai-test openmpi --mape --build

# Run the package's test suite (implies --build) and trigger automated 
# bisection if a regression is found
spack ai-test openmpi --mape --test --bisect
```

### Compute Node / CI Mode
```bash
# Execute specs previously generated by --plan-only (requires no internet)
# Ideal for execution in isolated HPC compute nodes
spack ai-test openmpi --execute-queued --test --bisect
```

### Context & Configuration Overrides
```bash
# Only generate specs for locally installed compilers (avoids queuing for CI)
spack ai-test openmpi --mape --local

# Specify a custom model and knowledge base path
spack ai-test openmpi --mape --model gpt-4o --kb ./my_kb.json

# Disable RAG (pattern mining and version gap analysis) for A/B testing
spack ai-test openmpi --mape --no-retrieval
```

You can configure defaults in `~/.spack/ai_test.yaml`:
```yaml
ai_test:
  model: gemini-2.5-flash
  kb: ~/.spack/cache/ai_test/kb.json
```

## System Architecture

The pipeline consists of the following modules:
- `cmd/ai_test.py`: The main CLI entry point that routes flags.
- `extract/`: Extracts package metadata (versions, variants, conflicts) and calculates initial structural risk signals (e.g. unbounded versions, C++ ABI sensitivity).
- `mape/analyze.py`: Computes historical failure rates and multiplies them with structural signals to prioritize high-risk dependencies.
- `mape/retrieval.py` & `mape/metrics.py`: Assembles the RAG context (KB pattern mining, Spack registry gap analysis, and GitHub issue scraping).
- `mape/plan.py`: Prompts the LLM (OpenAI, Anthropic, or Google Gemini) with the assembled context to generate target specs.
- `mape/execute.py`: Performs static pre-validation, concretization, compilation, and log-based failure classification.
- `mape/bisect.py`: Orchestrates the exponential galloping and binary search for defect localization.
- `kb/store.py`: Manages the atomic, hash-versioned JSON Knowledge Base.
